# Submission checklist

Everything below comes straight from the brief. Most of these lose marks for reasons that have nothing to do with how good the project is, which makes them the cheapest marks to protect.

## The deadline

**2 November 2026 at 23:59.** Submitted on Blackboard, under the Content link, at Project Documentation Submission.

The brief is blunt about this:

* Only one submission is allowed.
* Nothing submitted after 23:59 is accepted.
* Do not change the documents after submitting, because changed documents will not be considered.
* It is your responsibility to send it to the correct link.
* It is your responsibility to check that the file is a correct PDF.

Submit a day early. There is no version of this where submitting at 23:50 is a good idea.

## Before submitting

### The declaration

* [ ] The declaration exists in the document
* [ ] Every one of the ten members has signed it
* [ ] Signatures are real, not typed names

Without this the project is not marked at all. Check it twice.

### Formatting

* [ ] Arial
* [ ] Size 12
* [ ] Line spacing 1.5
* [ ] Text justified
* [ ] Grammarly certificate or results report included in the document

The rubric says directly that marks are deducted when the format is wrong or the Grammarly report is missing.

### Content

* [ ] AI solution and relevance to the theme, one paragraph
* [ ] Business objectives, success criteria and background
* [ ] Requirements, constraints and risks
* [ ] Initial assessment of tools and techniques
* [ ] Problem definition, 250 words or fewer, with the problem itself at 190 words or fewer
* [ ] Machine learning approach
* [ ] Data, with an example of every form of data used
* [ ] Model evaluation, and the time series analysis with a sample
* [ ] Solution techniques, including how the model improves its accuracy
* [ ] NLP, speech recognition or speech synthesis
* [ ] Deep learning
* [ ] Chatbot or softbot
* [ ] List of all group members
* [ ] Everything referenced properly

### The other deliverables

* [ ] Poster, soft copy
* [ ] Presentation, submitted with the documentation before the due date
* [ ] Practical solution working, and a backup video recorded

### The file itself

* [ ] Exported as PDF
* [ ] Opens correctly, on a different machine
* [ ] Nothing missing or cut off in the export
* [ ] Named sensibly
* [ ] Backed up in at least two places, for example this repository and Google Drive or OneDrive

The brief points out that as IT students you are expected to use cloud storage, and that a stolen or broken laptop will not be accepted as a reason. Back it up now, not in October.
